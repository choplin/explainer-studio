# style: zundamon
# Sample dialogue — a two-speaker audio guide.
# A = 四国めたん(学習者／まだ分かっていない側), B = ずんだもん(解説役).
#
# Note the shape: A is not a host handing out questions. A keeps being WRONG in the
# way a real listener would be wrong, and B has to break each wrong idea. Delete A's
# turns and B's turns no longer stand alone — the reason for every design decision
# disappears with them. That is the test a dialogue script has to pass.

A: 今日はある技術ドキュメントを読んでいくわね。大きなPDFを、章立てを保ったままMarkdownのレポートに変換する仕組みの話。
B: よろしくなのだ。
A: でもこれ、要するにPDFを丸ごとAIに読ませて「まとめて」って頼むだけの話でしょう？
B: それだと崩れるのだ。何百ページもあると、後半を読んでいる頃には前半を忘れているのだ。
A: あら。じゃあ細かく区切って、順番に読ませればいいのかしら。
B: 区切るのは正しいのだ。でも区切っただけだと、今度は章が境目でちぎれるのだ。
A: ちぎれる、というのは？
B: 三章の途中でチャンクが切れると、片方は見出しを知らないまま中身を読み、もう片方は中身の前半を知らないまま結論を読むのだ。
A: それぞれが、自分の見ている範囲では正しいことを書いてしまうのね。
B: そうなのだ。そして繋ぎ合わせると、同じ章の説明が食い違うのだ。
A: なるほど。それで、どうするの。
B: 忠実に写す仕事と、意味を汲む仕事を、別の担当に分けるのだ。まず各チャンクは、見出しをそのまま書き写すことだけに集中するのだ。
A: 要約はしないの？
B: させないのだ。解釈を混ぜると、チャンクごとに違う解釈が生まれて、あとで直せなくなるのだ。
A: つまり、最初の担当はただの書き写し係、ということかしら。
B: 近いのだ。でも「ただの」ではないのだ。見出しの列を正確に写すからこそ、あとから全部の見出しを繋ぎ直して、文書の背骨を復元できるのだ。
A: ああ、その背骨が先にできてから、はじめて中身を要約していくのね。
B: そういうことなのだ。
